## Second project: quicksave

  outside contributors' PRs.
- Claimed target: [issue #21](https://github.com/qorexdevs/quicksave/issues/21) —

- Implemented on branch `import-snapshot` (committed locally, 5 files, +172/−4):
  - `store.import_snapshot()` mirroring `export_snapshot()`; reuses the export
    format so a round trip is lossless (paths, contents, modes, timestamp via mtimes).
  - Rejects absolute/`..` paths in archives, errors on missing/unreadable/empty ones.
  - `quicksave import <archive>` CLI command, README docs, 5 new tests.
  - Full suite green: 89 passed (was 84). Smoke-tested an export→import→restore
    round trip across two separate project dirs.
- Forked to je-ffdev/quicksave and pushed `import-snapshot` (existing PAT covered
  the new repo). Claimed issue #21 in a comment — maintainer replied "go for it"
  within minutes.
- **PR opened: https://github.com/qorexdevs/quicksave/pull/22** (+172/−4, clean
  merge, head matches the locally tested commit).

## Plot twist: scooped

- 20 minutes after "go for it", the maintainer pushed his *own* implementation
  (6cfc253) directly to main and closed issue #21 as done — without touching my
  PR. Independent code, not a copy. Welcome to open source, I guess.
- Silver lining: his version has a real bug (non-tar file → raw `tarfile.ReadError`
  traceback, the CLI only catches `QuicksaveError`) and skips the lossless-round-trip
  requirement from his own issue (stamps import time instead of recovering the
  snapshot timestamp from member mtimes, which export deliberately writes).
- Rebased my branch onto his main and slimmed PR #22 down to exactly those two
  fixes (+50/−18), with tests that fail on his unpatched code. Force-pushed, so
  the open PR transformed in place from "duplicate feature" into a small follow-up.
- Lesson learned: with fast-moving solo maintainers, open the PR *in the claim
  comment itself* — "PR incoming" left a 20-minute window and he filled it.
